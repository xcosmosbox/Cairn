## Reproduction and limits

Default free tests are `go test -race -count=1 ./build/internal/constructionplan`.
The optional `TestLegacyArchiveCompatibilityFromSuppliedFiles` requires four explicit local inputs:
`CAIRN_PLAN_MANIFEST`, `CAIRN_PLAN_ARCHIVE_ROOT`, `CAIRN_PLAN_CORPUS` and the independently expected
`CAIRN_PLAN_MANIFEST_SHA256`. It reads dependency bytes without writing the archive, corpus, graph or
network. It skips when no external fixture inputs are supplied and fails when only some are supplied.
Tests never create a fake passed manifest for a newly generated annotation.

Synthetic regression coverage includes dependency absence/tampering, null/false/missing/error pass,
wrong round/ownership/method/ID, mismatched detail/SourceSpan despite rehashed metadata, duplicate or
empty records, shared source incidences, canonical input/completion ordering, 32/33 unique-unit boundaries,
copy isolation and precise incomplete609 status. Final exact source, command exits, logs, CI and separate
reviews are recorded in #75/its PR; do not infer those outcomes from this document's existence.

The remaining builder is not implemented. Root's prospective mapping contract filters eligible FTS hits
before LIMIT at Entity/Concept15, Subdomain4, Domain2 per unit, with deterministic rank/UUID/birth ties;
selected hits plus all ancestors must fit480/64/32 caps. Retrieval uses full name plus first40 Unicode
content runes only, chosen from the first canonical(docID,memberID) incidence for shared04 units;
model input retains EVERY complete source incidence's name/content/detail and selected summaries. Overflow needs
ordered bisection/recomputation against the same snapshot and singleton failure. Canonical names/summaries
are capped256/1024 bytes, mapping decision/group2048 bytes, total32768 bytes with complete unit/group
coverage; a32-unit batch is not promised to fit. The existing120-rune alias helper is insufficient.

Future description output uses `M`, the canonical JSON UTF-8 bytes of the complete ordered
`(docID,memberID,path/hash,name,content,detail)` incidence array, and per-node encoded-string cap
`C=min(24576,max(2048,2*M+512))` including quotes/escapes. Canonical greedy same-Subdomain batches
have≤8 nodes and aliases `n1..n8`; `sum(C+256)+512≤32768`, per-record non-description overhead≤256,
envelope/separators≤512 and an independent final size assertion. All input fields/incidences remain,
including valid optional empty Detail; source binding and nonblank generated descriptions are required.
This engineering cap applies compression pressure without proving semantic completeness or historical
quality equivalence. Full-input overflow bisects before dispatch, singleton overflow stops; max2 finite
batch attempts use fixed sanitized repair, with no partial accumulation or fallback.

Future relation work covers same-Subdomain unordered pairs across blocks plus OTHER-Subdomain K15
Entity/Concept candidates filtered before LIMIT; cross-candidate recall remains restricted. Packs have
at most48 unordered pairs and64 distinct nodes. Each pair may yield both directions ×6 kinds=12 triples;
canonical tuple/separator≤48 bytes, pair overhead≤96, envelope≤512, yielding a32768-byte whole-response
ceiling. Explicit empty pair results are allowed; unknown/duplicate pairs/triples fail. No model edge
prose: deterministic full-name typed descriptions lose model rationale and have no quality-equivalence
claim. Full node descriptions remain input. Exact wire plus65536 reserved tokens must fit1M before any
dispatch; bisect deterministically, never trim, singleton overflow fails. The32768 reasoning planning
allowance within65536 is not a provider-enforced split. Max2 logical attempts use fixed sanitized
feedback; actual stop/parse/coverage/limits fail closed. Actual catalogue pair/call counts must precede
a paid relation stage; no such admission receipts exist here. New cross/local-contradiction relations
receive one source verification. Implemented description batching, safe durable resume and atomic publication are
still separate future work. See ADR0007 for the full prospective contract.

No full incremental.Run, full-taxonomy/full-graph or unbounded
fallback is allowed by this phase. New #73 receipts are a different format/method and need a separately
scoped validated adapter after existing ID assignment; unsupported input fails closed.

The old #63 outcome remains FAILED. No provider/model/canary/paid control, QA/gold/HOLDOUT, full609
construction, schema/Bundle/query/default/dependency or release action occurred in this phase.
